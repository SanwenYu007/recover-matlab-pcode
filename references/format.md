# 旧格式 P-code 与保真验证

## 支持范围

解析器仅识别精确文件头 `v01.00v00.00`。该头不保证所有 MATLAB 语法的编码都在当前映射表内。未知格式、未知 token、截断索引或不能解码的文字均应明确报告；不得跳过后宣称恢复完整。

## 已观察到的结构

| 字节位置 | 内容 | 编码 |
|---|---|---|
| 0–5 | 主格式标识 v01.00 | ASCII |
| 6–11 | 次格式标识 v00.00 | ASCII |
| 12–15 | 扰乱参数 | 大端 uint32 |
| 16–19 | 上游命名 crc 的字段 | 大端 uint32；本工具没有实现其算法 |
| 20–23 | 保留字段 | 大端 uint32 |
| 24–27 | 压缩数据长度 | 大端 uint32 |
| 28–31 | 解压数据长度 | 大端 uint32 |
| 32 起 | 扰乱后的 zlib 数据 | 4 字节小端字与固定表 XOR |

扰乱表起始位置为 `(scramble >> 12) & 255`。第 i 个小端字与 `SCRAMBLE_TABLE[(i + seed) & 255]` 异或；最后不足 4 字节的尾部保留。解扰后用 zlib 解压，并严格核对声明长度、流结束与尾部数据。最大解压大小为 64 MiB。

解压数据前 28 字节为 7 个大端计数。计数总和给出后续以 NUL 结束的符号数量。符号边界按原始字节确定，再按 UTF-8 解码。剩余字节表示单字节关键字/运算符 token 或双字节符号引用。

双字节引用编号：`128 + 256 * ((first & 0x7f) - 1) + second`。负数、越界和截断必须报错。格式细节来自开源实现及本地重编码验证，属于观察到的私有格式，不是 MathWorks 公布的稳定接口。

## 影响正确性的解析细节

- 不将 UTF-8 字符数当作字节偏移；否则中文符号会移动后续 token 起点。
- 按 token 边界输出文字，不对字符串内容作正则格式化。
- `obj.method(...)` 不能被写成行首命令式 `obj .method (...)`；即使后者有时可解析，也会改变符号分类。
- `if` 等关键字需要词边界；清缓存等命令的参数之间也需要边界。
- token 61 是非共轭转置 `.'`；上游的内部标签 dottrans 不能作为源码。
- 保留 token 流末尾的换行数量；额外添加源码末尾换行也会改变重编码载荷。
- 不把空映射或内部 token 名称当成合法 MATLAB 语法。

## 证据层次

每次恢复记录原始 `.p`、源码和证据的 SHA-256。MATLAB 验证在独立临时目录复制源码后重新生成 P-code，记录同次清单、源码和重生成 P-code 的哈希。Python 比对步骤再次核对这些哈希，分别比较完整文件与解压后的完整载荷。

完整载荷包含计数、全部符号和全部语句编码。其一致性比“解压成功”或“语法通过”更强。即使完整载荷一致，原始排版、普通注释和实际运行环境行为仍不能由此推断。与原入口同名的依赖类也须有自己的文件才能恢复。
