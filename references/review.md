# 还原源码的对比与逻辑审查

本流程仅在用户要求比较或审查时使用。先确认文件的验证状态；未验证的解析文本可作线索，但不能把解码错误认定为原程序漏洞。

## 对比内容

- 对原始文件计算哈希识别完全重复的副本，再用载荷和源码比较判断版本差异。目录位置不同可能改变相对资源定位。
- 列出每个文件的入口/类、主要职责、方法和调用方。分清 UI 调度、业务服务、旧实现、配置与验证器。
- 沿真实入口追踪实际调用。一个事务、备份或校验类存在，不代表按钮流程调用了它。
- 区分显式未实现、兼容性限制和有意策略；不要只根据文件名推断功能。

## 优先检查的逻辑边界

| 输入或操作 | 核查问题 |
|---|---|
| 工作簿/配置中的文本 | 数据是否进入 eval、evalin、str2num；信任边界和标识符/字面量校验是否明确 |
| 生成脚本 | 字符串引号是否转义；生成失败前是否先删旧文件 |
| 输出路径 | 用户字段是否包含分隔符、..、驱动器/UNC；最终规范路径是否处于预期根目录 |
| 生成/发布 | 是否只发布本次成功且完整的产物；逐文件覆盖失败后有无回滚 |
| 模型/字典 | 是否修改源模型、保存无关的未保存编辑，或删除设计数据；所有权与备份是否覆盖异常路径 |
| 数据契约 | 列是否按列名映射；继承维度是否被静默猜为标量；整数和精度转换是否符合目标语义 |
| 状态和清理 | 原异常是否被二次清理异常覆盖；失败是否被误报成功 |

动态执行函数的出现本身不是漏洞。预加载脚本可能是明确的业务功能；只在数据来源和权限边界构成实际风险时报告。许可验签公钥也不是私钥泄漏。不得为了审查去修改或移除许可证执行逻辑。

## 每条发现应包含

具体源码位置、可触发输入/状态、真实调用链、预期与实际行为、后果、修复建议，以及证据属于静态推导、独立规则反例还是模型集成复现。单独标识未接入入口的服务问题和需要项目模型验证的条件。

独立规则反例应使用无破坏性的输入并保持原文件不变。恢复/语法验证不授权启动 GUI、运行载入脚本、构建模型、执行发布/删除或更改许可证。需要这些行为验证时，遵循用户给定的执行范围。

输出可以包括职责 CSV、调用关系和按影响排序的报告；按任务需要选择，避免把命名/排版提示混入逻辑漏洞计数。查 MATLAB/Simulink API 语义时优先匹配安装版本的本地 help 或官方文档。可按任务使用 matlab-review-code 技能。
